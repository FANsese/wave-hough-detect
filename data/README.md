# Data

## 1. Simulation data for §3.1 (Figures 2–8) — included, nothing to download

All data used in the simulation study is **generated by code in this repository**:

| Paper | Generator | Command |
|---|---|---|
| §3.1.1, Figs 2–5 (8×8 linear wavefronts, FPR/FNR) | `src/wave_hough_detect/simulate.py` → `simulate_linear_wavefronts()` | `python examples/demo_simulation.py` |
| §3.1.2, Figs 6–8 (96×96 circular wavefronts, estimation accuracy) | `src/wave_hough_detect/simulate_circular.py` → `simulate_circular_wavefronts()` | `python examples/demo_simulation_circular.py` |

The simulators are seeded deterministically from their parameters — R starts from
`set.seed(SEED_BASE × Π(parameters) + seed.shift)` and the Python port reproduces that arithmetic,
so the same parameter set always yields the same dataset. Note that **R's random numbers cannot be
reproduced in Python** (different generators), so the port is statistically equivalent to the R
simulation, not bit-wise equal. See [`../docs/reproducibility-notes.md`](../docs/reproducibility-notes.md).

## 2. A synthetic recording in the §3.2 input format — included

To make the real-data pipeline runnable without the experimental recording, the repository can
write a CSV in the **exact format** the pipeline expects:

```python
from wave_hough_detect import simulate_recording
simulate_recording("synthetic_recording.csv")   # 90 000 rows × 65 columns
```

Then:

```bash
python examples/demo_pipeline.py --data synthetic_recording.csv
```

or simply run `python examples/demo_simulation.py`, whose part ③ does both and then **checks the
fit against the ground truth it generated** (source position, speed and excitation times are all
settings of the generator, and the pipeline recovers them).

The synthetic trace reproduces the structure of the real input: 64 electrodes numbered row-major on
an 8×8 grid, a time column in milliseconds, negative-going extracellular field potentials, a slow
baseline drift, and several propagating wavefronts originating outside the grid to the south. It
does **not** reproduce the published numbers, and it is not a substitute for the experimental data.

> ⚠️ **One trap, worth stating up front.** The time column must be in **milliseconds**. The
> pipeline divides the time axis by 200 before the Hough transform, and that division is a
> *conditioning scale* — it brings the time coordinate into the same range as the grid coordinates
> `x, y ∈ [1, 8]` so that a single inlier tolerance works for all three axes. It is **not** a unit
> conversion. A time column written in units of 1/200 ms makes the Hough geometry meaningless: the
> pipeline then reports `v ≈ 0` and `t₀ ≈ ±2×10⁷`. This was verified by running both conventions.

## 3. The experimental recording — not included

The recording analysed in §3.2 of the paper is:

```
CM_PIN_Control_2N30_Aunor_2_input_60000.csv
```

extracellular field potentials from cultured Sprague-Dawley rat cardiac myocytes (embryonic day
16–19) on a 64-channel (8×8) planar gold MEA, recorded under control, normoxic conditions
(92.5–95.2 % dissolved O₂).

**It is not distributed here.** The recording was produced by a collaborating laboratory and the
authors do not hold the rights to redistribute it. The culture and recording protocol is described
in:

> Yeung, C.-K., Sommerhage, F., Wrobel, G., Law, J.K.-Y., Offenhäusser, A., Rudd, J.A.,
> Ingebrandt, S., Chan, M. *To establish a pharmacological experimental platform for the study of
> cardiac hypoxia using the microelectrode array.*
> J. Pharmacol. Toxicol. Methods **59**(3), 146–152 (2009).
> <https://doi.org/10.1016/j.vascn.2009.02.005>

Only the numerical values in Tables 2, 3 and 4 depend on this file. Everything else in the paper —
the method, the simulation study, the pipeline itself — is reproducible from code alone.

If you do have the file, put it anywhere and point the code at it:

```bash
python examples/demo_pipeline.py --data /path/to/recording.csv
# or
export WHD_DATA=/path/to/recording.csv
pytest tests/test_paper_tables.py     # checks Tables 2/3/4 digit by digit
```

## 4. Gastric pilot data — not included

A separate 64-channel gastric slow-wave MEA recording, kindly provided by Prof. John A. Rudd,

cardiac recording analysed in §3.2, and its analysis code (spatial spike-distance histograms) is

## 5. Input format reference

For anyone substituting their own recording:

| Requirement | Detail | Why |
|---|---|---|
| Delimiter / header | comma-separated with a header row | `pandas.read_csv` |
| Column 1 | time stamps, numeric, **in milliseconds** | see the trap in section 2 |
| Columns 2…65 | one per electrode, numeric | 64 electrodes expected |
| Column names | any name whose **3rd and 4th characters** are the electrode number, e.g. `Ch01` … `Ch64` | the original R code parses `substr(name, 3, 4)`; the port accepts `Ch01`-style names |
| Electrode numbering | 1…64, row-major on the 8×8 grid | `channel_to_xy()` |
| Signal polarity | negative-going spikes; detection takes the running minimum | `detect_spikes()` |
| Sampling | 10 kHz assumed; the filter cutoff is `1/500` of Nyquist, i.e. 10 Hz | `butter_highpass()` |
| Duration | a few thousand ms. The `t/200` conditioning means the time axis should span roughly 200×8 to 200×45, i.e. ≈ 1600–9000 | `TIME_SCALE` |

For a different number of channels, set `grid_side` in `simulate_recording()` and change the `40` in
the plane-acceptance test (it is two thirds of the electrode count) — that constant is inherited
from the published code and is **not** derived from the grid size.
